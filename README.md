这是基于 [longhengmu/GloryOfKings-Plugin](https://gitee.com/longhengmu/GloryOfKings-Plugin) 的完整业务核心适配项目。保留原版 **40 个模块、101 条命令路由、32 份 HTML 模板**，通过常驻 Node 核心对接 AstrBot 的消息、权限、数据目录及后台任务。另补充 AstrBot 管理命令和 `glory_of_kings` LLM 工具。

本版基准提交：[`86ac5b675163`](https://gitee.com/longhengmu/GloryOfKings-Plugin/commit/86ac5b6751630eadb34719aa2a56591c53767e0e)，提交时间 2026-09-22，检出时间 2026-09-24。后续更新、问题修复以此仓库的提交为上游依据。

> 观战直播、营地消息及共享库的客户端已接入。它们所需的服务端由上游作者单独分发，不包含在公开仓库中，需自行取得服务地址和接入令牌。本包没有伪造接口或附送私人密钥。真实游戏查询需要有效的营地登录态，并受上游接口权限、隐私设置及频控影响。

## 安装

仓库地址：[https://github.com/wzq10314/astrbot_plugin_gloryofkings](https://github.com/wzq10314/astrbot_plugin_gloryofkings)。可在 AstrBot 插件管理中使用该 Git 仓库地址安装，或从 [Releases](https://github.com/wzq10314/astrbot_plugin_gloryofkings/releases) 下载 ZIP。

1. 在 AstrBot 后台的插件管理中上传 `astrbot_plugin_gloryofkings-v1.0.4.zip`，然后启用插件。
2. 环境需要 **Python 3.12、Node.js 22+、npm**。Python 依赖随安装包安装，Node 依赖首次启动自动准备。已安装 RConsole 的机器可以复用系统 Node 和 Chromium；两个插件的数据、账号和依赖目录独立。
3. 管理员私聊机器人发送 `#王者依赖状态`。浏览器就绪的判断包含一次真实启动和截图。未就绪时可发 `#王者浏览器安装`，依赖安装失败时可发 `#王者依赖安装`。
4. 先发 `#王者帮助` 检查图片，再按下方步骤登录和绑定。

依赖准备可能需要几分钟。默认 npm 镜像是 `https://registry.npmmirror.com`，可在后台修改。优先复用系统 Chromium；Debian/root 容器默认允许补装浏览器及系统库。可通过 `engine_auto_browser_system` 关闭系统包自动安装。

手动安装时，解压后的目录应为 `/AstrBot/data/plugins/astrbot_plugin_gloryofkings/main.py`，不能再套一层同名目录。保存后重载插件。详细说明见 [安装与排错](docs/INSTALL.md)。

## 第一次使用

在**机器人私聊**中选择与你账号对应的登录方式：

```text
#营地QQ全局登录
#营地wx全局登录
```

用你自己的手机账号扫码确认。原版会保存营地登录态，并将归属人设为发起登录的 QQ；请不要把二维码交给别人扫。登录后的全局账号池供查询轮询使用，营地好友、观战和消息仍按账号归属校验。

在需要使用插件的群中绑定查询对象：

```text
#绑定营地 你的数字营地ID
#王者主页
#查询战绩
```

原版要求手动绑定在群内进行；扫码成功也会自动绑定扫码得到的营地账号。绑定营地ID与取得查询登录态是两回事：只绑定数字不能代替扫码登录。

## 自然语言调用

默认开启 `llm_enabled`。在 AstrBot 中选择支持工具调用的模型，并允许当前人格/会话使用 `glory_of_kings` 工具，即可说：

```text
帮我看看最近的王者战绩
查一下第三场对局
妲己现在怎么出装？
看看我的皮肤墙
我这周打得怎么样？
帮我开启这个群的战绩推送
帮我登录王者营地，用QQ扫码（私聊）
```

工具直接调用原版命令并发送图片，返回实际提示给模型。未绑定、接口失败、权限不足会如实返回；同一条消息里重复调用同一命令会去重。身份和目标群来自当前事件，模型不能改成另一个群或冒充管理员。

查询、本人绑定/切换/删除、扫码、群订阅、观战及本人消息开关支持自然语言。密钥配置、服务部署、批量清理和向营地好友发送私信仍需用户直接发命令，避免把凭据交给模型或误发消息。模型是否正确选择工具还受模型能力和人格配置影响。

## 配置与账号管理

原版配置项已接入 AstrBot 插件设置，包括推送时间、缓存、服务地址、共享开关和认证请求默认参数。`config.yaml` 是默认值文件；主要配置入口是 AstrBot 后台。

黑名单请使用本插件的 `blackList` 设置或原版黑名单命令。AstrBot 4.28.1 标准配置没有云崽全局黑名单的等价字段，`blackListFollowGlobal` 仅在宿主额外提供兼容字段时生效。

锅巴专属页面用 AstrBot 配置与管理员私聊命令替代：

```text
#王者账号管理 列表
#王者账号管理 归属 营地ID QQ号
#王者账号管理 消息 营地ID 开
#王者账号管理 消息 营地ID 关
#王者账号管理 全局 营地ID 开
#王者账号管理 删除 营地ID
#王者配置 quoteReply false
```

必要时管理员可私聊 `#王者账号管理 导入 原版账号JSON` 导入自己的现有账号；更推荐扫码。列表不回显 token/userKey。调整 cron 后重载插件。命令写入的设置会保留，后台配置字段发生改变时再覆盖对应值。

多机器人按“平台 ID + 机器人 QQ”分目录和进程运行。若多个机器人各自部署观战/消息服务，用 `bot_overrides` 为不同机器人指定不同服务端口和地址；不要让多个独立账号池管理同一个营地消息服务。

## IM 私聊限制

营地好友列表、发消息、消息开关、服务状态、接入与部署均只允许私聊；管理员也不能在群里调用。LLM 遵循同一限制。群里仅返回转到私聊的提示，不查询好友、不回显消息内容。引用回复只处理私聊中的已知营地消息。

正常消息推送给账号归属人的私聊，无归属账号不推送。保留上游的投递失败处理：若归属人私聊不可达，会把失败消息转告机器人管理员私聊，不会转发到群。发送到群的原始内容仍可能被 QQ 或其他日志插件记录，请不要在群里输入凭据或聊天正文。

部署步骤见 [IM 安装说明](docs/INSTALL.md#im-私聊启用步骤)。

## 服务依赖自动安装

从 v1.0.3 开始，观战和 IM 的接入/部署命令会在启动服务前自动安装服务目录中的生产依赖；有锁文件时使用 npm ci，另补充上游部分 IM 版本遗漏的 ws。安装成功后再次检查模块可解析性；失败时不启动新服务。依赖清单不变且模块齐全时不重复安装。下载使用后台 engine_npm_registry。

旧用户重载新版后发 `#营地消息部署` 或 `#营地观战部署`，即可在相应部署流程中自动补齐。此命令也会获取作者当前服务包，不是仅重启服务。安装包携带自动安装逻辑和核心依赖锁文件，不包含跨平台 node_modules；首次安装仍需联网。Node.js 22+、npm 和观战用 ffmpeg 仍是宿主前置条件，Chromium 沿用已有自动准备机制。外置服务仍需作者分发授权，不会随插件自动开通。为避免安装脚本副作用，外置服务依赖安装禁用生命周期脚本；未来若出现需要原生编译的依赖，需进一步适配。

## 上游更新与数据保留

- 上游源码原样保存在 `engine/upstream`，逐文件摘要及提交号在 `UPSTREAM.json`。
- `#王者更新` / `#王者更新日志` 在适配版中用于核对上游最新提交。实际安装使用 AstrBot 插件管理和新的适配包，不直接运行云崽更新器。
- 维护者使用 `scripts/stage_upstream.py` 准备下一版本并对比文件变更，按 [维护说明](docs/UPSTREAM.md) 验证后发布。
- 运行状态在 AstrBot 的 `data/plugin_data/astrbot_plugin_gloryofkings/`，包括账号池、绑定、订阅、归档、消息游标和下载的服务。更新插件源码不会覆盖该数据目录。
- 普通 OneBot11 不显示原版 QQ 官方机器人交互按钮，功能可通过对应命令或自然语言调用。

## 验证范围

v1.0.3 通过 30 项 Python 集成测试和 14 项 Node 渲染/存储断言：包括完整模块加载、权限、持久化、LLM 路由、真实帮助图片、真实 canvas 趋势图、扫码浏览器会话隔离、账号归属及消息去重。

测试使用虚拟 OneBot 传输及模拟游戏数据，**本地测试未使用真实游戏账号扫码，也未取得作者私有服务进行端到端验证**。外部接口变化需结合实际运行结果继续修复。上游自带部分测试依赖作者未公开的本地文件，本项目提供了不需要私人账号的替代回归测试。
