# 安装与排错

目标环境：AstrBot 4.28.1 / Python 3.12 / OneBot11 / NapCat，Linux Docker 优先。

## 安装包

在 AstrBot 插件管理上传 ZIP。确保目录中同时存在 main.py、metadata.yaml、_conf_schema.json、engine/package-lock.json 和 engine/upstream，不能只复制 main.py。

已有 RConsole 环境通常已有 Node/npm/Chromium，插件会复用系统浏览器。Node 依赖按本项目 lockfile 安装到本项目 engine/node_modules，不需要手动复制另一个插件的 node_modules。

初次安装后管理员私聊发：

```text
#王者依赖状态
#王者帮助
```

## 缺少依赖

确认是在 AstrBot 容器内安装，不是只装在宿主机。

```bash
docker exec astrbot node --version
docker exec astrbot npm --version
docker exec astrbot chromium --version
```

Node 需要 22 或更高版本。你此前已配置 RConsole 时无需重复安装。插件会自动安装其余 Node 依赖；失败时可修改后台 engine_npm_registry 后发 `#王者依赖安装`。

Debian/root 下浏览器自动准备失败，可在宿主机运行：

```bash
docker exec -u 0 astrbot sh -c 'apt-get update && apt-get install -y --no-install-recommends chromium fonts-noto-cjk'
```

完成后发 `#王者浏览器安装` 重新检测。依赖状态必须出现“已实际启动浏览器并截图”，仅显示安装了 npm 不代表图片就绪。下载慢时检查当前容器的系统软件源和网络，插件不擅自改写软件源。

若使用自定义浏览器路径，在后台 `browser_path` 填写容器内路径，如 `/usr/bin/chromium`。

系统包安装在容器可写层，重建容器可能丢失。建议在你原有 Dockerfile 中加入上述 apt 安装步骤，并把 `/AstrBot/data` 持久化。

## 登录与绑定

登录：私聊 `#营地QQ全局登录` 或 `#营地wx全局登录`，收到二维码后用对应账号扫码。
绑定：群里 `#绑定营地 数字营地ID`。本版保留上游的群内绑定规则；扫码成功也会自动绑定登录得到的营地ID。

原版“全局登录”意味着该登录态可作为机器人查询池使用，不代表把好友消息发给所有群。IM 推送根据 ownerBotUserId 只交给归属用户。

QQ群中查询报登录态缺失：先由账号本人私聊扫码，不需要把凭据发给聊天模型。

## 自然语言没有调用工具

1. 确认后台 llm_enabled 已开启。
2. 确认当前模型支持工具调用，并允许当前会话/人格使用 glory_of_kings。
3. 先说“调用王者工具查询我的战绩”验证；日志应出现 glory_of_kings。
4. 工具调用成功后会直接发送图片。模型看不到图中所有信息时不应编造数据；可以让它改用准确的查询命令。
5. 历史对话可能保留旧能力描述，可新建机器人会话测试。

## 自动推送发到哪里

在希望推送的群里发 `#开启战绩推送` 等命令。个人订阅按用户和群保存；群日报与皮肤上新需群管理权限。不要在私聊中开启群订阅。

定时任务随插件加载运行，不依赖当天是否有人发过命令。机器人连接后后台每 30 秒检查核心状态，每 5 分钟刷新群成员索引；网络中断时推送仍可能失败。

## 观战和营地消息

向指定上游作者取得分发地址和令牌后，由管理员私聊发送：

```text
#营地观战接入 地址 令牌
#营地消息接入 地址 令牌
```

对应原版会下载外部服务，使用隔离的 PM2 目录管理进程。观战另需 ffmpeg，直播网页需要对外可访问地址、容器端口映射及防火墙放行。填写 watchPublicUrl 后群友才可打开，127.0.0.1 仅对服务自身有效。

消息服务部署后，本人发送 `#营地消息开` 选择加入收消息名单。扫码进入账号池不会自动替你开启接收消息。

未取得服务端时，战绩等常规功能仍可用；观战/消息会明确提示未接入。公开源码不包含这些私有服务，本版无法替你生成作者令牌。

## 日志

```bash
docker logs --tail 150 astrbot
```

贴出依赖状态及 GloryOfKings 错误类型即可。不要发送账号池、备份包、扫码授权回调或带凭据的完整日志。插件桥接层不输出上游原始认证日志，但 AstrBot 的其他消息采集插件可能记录用户自己发送的配置命令。


## IM 私聊启用步骤

先安装 v1.0.2 或更新版本并重载。以下命令全部在机器人私聊执行。

1. 管理员发送 `#营地消息服务` 查看部署状态。
2. 如果同一机器人此前已用 `#营地观战接入` 保存了作者分发地址和令牌，可直接发送 `#营地消息部署` 复用接入信息。仅打开作者提供的观战网站不代表本机器人已经接入。
3. 未配置时，管理员发送 `#营地消息接入 分发地址 接入令牌`，不要把令牌贴到群里或提供给 LLM。
4. 再发 `#营地消息服务` 确认服务启动。用户本人通过 `#营地QQ全局登录` 或 `#营地wx全局登录` 登录自己的账号。
5. 本人发送 `#营地消息开`，再用 `#营地好友` 查询。要给营地好友发消息，直接发送 `#营地私聊 编号 内容`；LLM 不代发对外私信。
6. 收到营地消息后，在机器人私聊里引用回复。停止接收用 `#营地消息关`。

群聊使用上述 IM 命令时，仅提示转到私聊。管理员无例外；不要在群里做包含真实令牌、消息正文的测试。

验收建议：群里发 `#营地好友` 应只提示私聊；私聊发同一命令应查询本人已登录账号；让自己的营地好友发一条测试消息，确认只有机器人私聊收到。单纯绑定别人的营地ID不能获取其好友列表。


## 服务依赖缺失（v1.0.3 起自动处理）

出现 Cannot find package ws 时，更新插件、重载后私聊发送 `#营地消息部署`。接入和部署流程会自动安装依赖，再启动服务；观战部署同样支持。已有服务不会仅因插件更新就自动重启。若网络失败，检查 engine_npm_registry 后重试部署，无需逐个执行 npm install。Node/npm 和 ffmpeg 仍需由宿主提供。


## IM 能收不能发，错误码 -30003

上游实现记录该码与登录态失效相关。IM 实例可能仍持有旧凭据：先重启本机器人对应独立 PM2_HOME 下的 gok-im，让服务重新读取账号池。仍失败时，由本人私聊重新扫码登录，再重启 IM。不要反复重试发送，先确认对方是否收到；不同机器人的 PM2_HOME 不同，不要操作其他实例。无需重新部署服务或开放 8900 公网端口。
